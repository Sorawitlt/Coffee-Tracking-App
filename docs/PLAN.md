# Brew Log — แผนออกแบบแอปบันทึกและช่วยชงกาแฟ

> เอกสารแผนหลัก (Master Plan) ใช้อ้างอิงทุกขั้นตอนการพัฒนา
> สถานะ: v1.1 · อัปเดต 2026-11-09 (ขั้น 2: ปรับรายละเอียด Data model)

## 1. เป้าหมาย

| # | เป้าหมาย | ตัวชี้วัดความสำเร็จ |
|---|---------|------------------|
| 1 | **บันทึกเร็ว** | บันทึกการชง 1 ครั้งเสร็จใน ≤ 30 วินาที (กด "ชงซ้ำ" ≤ 5 วินาที) |
| 2 | **ช่วยชงได้จริง** | มีตัวจับเวลา + ขั้นตอนเทน้ำทีละสเต็ป ใช้มือเดียวได้ จอไม่ดับ |
| 3 | **ชงดีขึ้นทุกครั้ง** | แอปบอก "ครั้งหน้าควรปรับอะไร 1 อย่าง" จากผลชิม |
| 4 | **ใช้ได้ทุกเครื่อง** | มือถือ iOS/Android, แท็บเล็ต, คอมพิวเตอร์ — ใช้ออฟไลน์ได้ |
| 5 | **ข้อมูลเป็นของผู้ใช้** | Export เป็น CSV/Excel/Google Sheets และ Backup JSON ได้ตลอด |
| 6 | **ขยายได้** | โครงสร้างข้อมูลรองรับ ชา, มัทฉะ, โกโก้ และเครื่องดื่มอื่นในอนาคต |

**กลุ่มผู้ใช้:** มือใหม่ที่ชงที่บ้าน → Home barista → บาริสต้าร้านกาแฟ (Phase 2)

## 3. ฟีเจอร์ (Scope)

### Phase 1 — MVP (สิ่งที่จะสร้าง)

| โมดูล | รายละเอียด |
|------|-----------|
| **A. คลังเมล็ด (Beans)** | ชื่อ, โรงคั่ว, แหล่งปลูก, สายพันธุ์, Process (Washed/Natural/Honey/Anaerobic), ระดับคั่ว, **วันที่คั่ว → นับวันอัตโนมัติ**, น้ำหนักคงเหลือ (หักอัตโนมัติเมื่อชง), ราคา → **ต้นทุนต่อแก้ว** |
| **B. อุปกรณ์ (Gear)** | เครื่องบด (+สเกลเบอร์บด), อุปกรณ์ชง, กาต้มน้ำ, ตาชั่ง, ฟิลเตอร์ |
| **C. วิธีชง & สูตร (Methods & Recipes)** | สูตรตั้งต้น 8 แบบ (ดูข้อ 5) + สร้าง/บันทึกสูตรของตัวเอง |
| **D. ผู้ช่วยชง (Brew Assistant)** | คำนวณอัตราส่วน, ตัวจับเวลา, ขั้นตอนเทน้ำทีละสเต็ป (เป้าน้ำหนัก + เวลา), เสียง/สั่นแจ้งเตือน, จอไม่ดับ (Wake Lock) |
| **E. บันทึกการชง (Brew Log)** | ค่าที่ชงจริง, เติมค่าอัตโนมัติจากครั้งล่าสุด, ปุ่ม **"ชงซ้ำ"** |
| **F. ชิม & ให้คะแนน (Tasting)** | ดาว 1–5, สไลเดอร์ เปรี้ยว↔ขม / บาง↔หนา / หวาน, แท็กรสชาติ (อิง SCA Flavor Wheel แบบย่อ), โน้ตสั้น |
| **G. แนะนำการปรับ (Dial-in Advisor)** | กฎตัดสินใจ (Rule-based) บอก **"ปรับ 1 อย่าง"** สำหรับครั้งหน้า — ไม่ต้องใช้ AI, ทำงานออฟไลน์ |
| **H. ประวัติ & สรุปผล (Insights)** | ค้นหา/กรอง, สูตรที่ดีที่สุดต่อเมล็ด, กราฟคะแนนตามเวลา, กราฟ Brew Control Chart (TDS × EY) |
| **I. Export / Import** | CSV (UTF-8 BOM เปิดใน Excel ภาษาไทยไม่เพี้ยน), นำเข้า Google Sheets ได้, Backup/Restore JSON |

### Phase 2 — ต่อยอด (ยังไม่ทำ)

- Cloud sync + Login หลายอุปกรณ์ (Supabase หรือ Firebase)
- **Café mode:** หลายบาริสต้า, สต็อกเมล็ด, ต้นทุนต่อแก้ว, Export รูปแบบที่ map เข้า ERP (เช่น SAP: Material / Goods Issue) ได้
- เชื่อมตาชั่ง Bluetooth (Web Bluetooth — ใช้ได้บน Chrome/Android/Desktop, **ไม่รองรับ iOS Safari**)
- เครื่องดื่มอื่น: ชา, มัทฉะ, โกโก้, Cold brew tea
- AI ช่วยสรุปโน้ตรสชาติ (ตัวเลือก, ต้องมี API key)

## 4. หลักการออกแบบ UX

1. **ค่าเริ่มต้นฉลาด** — เลือกเมล็ด + วิธีชง แล้วค่าที่เหลือเติมจากครั้งล่าสุดทันที
2. **ฟิลด์จำเป็นน้อยที่สุด** — บังคับแค่: วิธีชง, เมล็ด, ปริมาณกาแฟ, น้ำ; ที่เหลือเป็นตัวเลือก
3. **ปรับทีละ 1 ตัวแปร** — แอปไฮไลต์ค่าที่ต่างจากครั้งก่อน เพื่อให้เห็นผลของการปรับชัดเจน
4. **ใช้มือเดียวได้** — ปุ่มใหญ่ (≥ 48px), ปุ่ม +/– สำหรับตัวเลข, ไม่ต้องพิมพ์ระหว่างชง
5. **อ่านง่ายในทุกแสง** — Light/Dark mode, ตัวเลขใหญ่ในหน้าจับเวลา

**โครงหน้าหลัก (Bottom navigation 4 แท็บ)**

```
[ ☕ ชง ]   [ 📖 บันทึก ]   [ 🫘 เมล็ด ]   [ 📊 สรุป ]
```

**Flow หลัก**

```
เลือกวิธีชง → เลือกเมล็ด → (ค่าเติมอัตโนมัติ) → เริ่มชง (Timer + ขั้นตอน)
   → จบ → ให้คะแนน/ชิม (10 วินาที) → บันทึก → แสดง "ครั้งหน้าลอง: บดละเอียดขึ้น 1 คลิก"
```

## 5. ความรู้กาแฟที่ฝังในแอป (Domain Rules)

### 5.1 สูตรตั้งต้น (Default Recipes)

| วิธีชง | กาแฟ : น้ำ | ตัวอย่าง | อุณหภูมิน้ำ | เวลารวม | ระดับบด |
|-------|-----------|---------|-----------|--------|--------|
| Espresso | 1 : 2 (กาแฟ : ช็อต) | 18 g → 36 g | 92–94 °C | 25–30 s | ละเอียดมาก |
| V60 / Pour-over | 1 : 16 | 15 g : 240 g | 92–96 °C | 2:30–3:30 | กลาง-ละเอียด |
| Kalita Wave | 1 : 16 | 20 g : 320 g | 92–96 °C | 3:00–4:00 | กลาง |
| Chemex | 1 : 16 | 30 g : 480 g | 93–96 °C | 4:00–5:00 | กลาง-หยาบ |
| AeroPress | 1 : 15 | 15 g : 225 g | 85–92 °C | 1:30–2:30 | กลาง-ละเอียด |
| French Press | 1 : 15 | 30 g : 450 g | 93–96 °C | 4:00 (+ พัก) | หยาบ |
| Moka Pot | ~1 : 7–10 | ใส่ผงเต็มตะกร้า, น้ำถึงวาล์ว | น้ำร้อนจัดตั้งต้น | 4–6 นาที | กลาง-ละเอียด |
| Cold Brew | 1 : 8 (หัวเชื้อ) / 1 : 12–15 (พร้อมดื่ม) | 100 g : 800 g | น้ำเย็น/อุณหภูมิห้อง | 12–18 ชม. (ตู้เย็น) | หยาบ |

**ตัวอย่างขั้นตอน V60 ใน Brew Assistant:**
`0:00 Bloom 45 g → 0:45 เทถึง 150 g → 1:15 เทถึง 240 g → ~2:45–3:15 น้ำหยดหมด`

### 5.2 สูตรคำนวณ

| ค่า | สูตร |
|----|-----|
| อัตราส่วน (Ratio) | `น้ำ ÷ กาแฟ` → แสดงเป็น 1 : x |
| วันหลังคั่ว | `วันที่ชง − วันที่คั่ว` |
| น้ำกาแฟที่ได้ (ประมาณ, Filter) | `น้ำ − (กาแฟ × 2)` (ผงกาแฟอุ้มน้ำ ~2 เท่า) หากไม่ได้ชั่งจริง |
| Extraction Yield (EY %) | `(น้ำหนักเครื่องดื่ม × TDS%) ÷ กาแฟ` |
| ต้นทุนต่อแก้ว | `(ราคาถุง ÷ น้ำหนักถุง) × กาแฟที่ใช้` |

**ช่วงเป้าหมาย (อ้างอิง SCA)**

| ประเภท | TDS | EY |
|-------|-----|----|
| Filter | 1.15–1.45 % | 18–22 % |
| Espresso | 8–12 % | 18–22 % |

> TDS ต้องใช้ Refractometer — เป็น **ตัวเลือก** ผู้ใช้ทั่วไปใช้ผลชิมแทนได้

### 5.3 Dial-in Advisor (กฎแนะนำการปรับ)

แอปแนะนำ **การปรับเพียง 1 อย่าง** ตามลำดับความสำคัญ: **ระดับบด → อัตราส่วน → อุณหภูมิ → เวลา/เทคนิค**

| อาการจากการชิม | การวินิจฉัย | ครั้งหน้าลอง |
|--------------|-----------|-----------|
| เปรี้ยวแหลม, บาง, จบสั้น, เค็ม | สกัดน้อยไป (Under-extracted) | บดละเอียดขึ้น 1 ขั้น (หรือ น้ำร้อนขึ้น 2 °C / เวลานานขึ้น) |
| ขม, ฝาด, แห้งปาก | สกัดมากไป (Over-extracted) | บดหยาบขึ้น 1 ขั้น (หรือ น้ำเย็นลง 2 °C / เวลาสั้นลง) |
| รสสมดุล แต่จืด/ใส | เข้มน้อยไป | เพิ่มกาแฟ (เช่น 1:16 → 1:15) |
| รสสมดุล แต่หนัก/เข้มเกิน | เข้มมากไป | เพิ่มน้ำ (เช่น 1:15 → 1:16) |
| ทั้งเปรี้ยวและขมพร้อมกัน | สกัดไม่สม่ำเสมอ (Channeling) | ปรับเทคนิค: เทให้นิ่ง, Swirl, กระจายผง/Tamp ให้เรียบ |
| Espresso ไหลเร็ว < 20 s | บดหยาบไป | บดละเอียดขึ้น |
| Espresso ไหลช้า > 35 s | บดละเอียดไป | บดหยาบขึ้น |
| อร่อยแล้ว (≥ 4 ดาว, สมดุล) | — | ⭐ บันทึกเป็น "สูตรที่ดีที่สุด" ของเมล็ดนี้ |

**ข้อความแนะนำเพิ่มตามวันหลังคั่ว:** < 4 วัน → "เมล็ดยังสดมาก อาจมีก๊าซเยอะ ควรพักก่อน" / > 45 วัน → "กลิ่นอาจลดลง ลองน้ำร้อนขึ้นเล็กน้อย"

## 6. โครงสร้างข้อมูล (Data Model)

ออกแบบให้ **รองรับเครื่องดื่มทุกประเภท** ผ่าน `category` และใช้ **UUID** ทุกตาราง (พร้อมทำ Cloud sync ภายหลัง)

```ts
Bean {
  id, name, roaster, origin, variety?, process?, roastLevel,
  roastDate, weightG, remainingG, priceTotal?, currency?,
  category: 'coffee' | 'tea' | 'other', notes?, archived, createdAt, updatedAt
}

Gear {
  id, type: 'grinder' | 'brewer' | 'kettle' | 'scale' | 'filter' | 'other',
  name, grindScale?: { min, max, step },  // สำหรับเครื่องบด
  notes?, createdAt, updatedAt
}

Recipe {
  id, name, method, category, isDefault,
  doseG, waterG, tempC?, grindHint, totalTimeSec,   // tempC ไม่ระบุ = ไม่เกี่ยวข้อง (Cold brew, Moka)
  steps: [{ atSec, action, targetWaterG?, label? }], // action = รหัสขั้นตอน (bloom/pour/press…) แปลผ่าน i18n
  createdAt, updatedAt
}

Brew {
  id, brewedAt, method, beanId, recipeId?, grinderId?, brewerId?,
  doseG, waterG, yieldG?, grindSetting?, tempC?,
  bloomSec?, totalTimeSec?, tds?, // คำนวณ: ratio, ey, daysOffRoast, costPerCup
  rating?: 1..5,
  balance?: -2..2,      // สไลเดอร์ เปรี้ยว(−) ↔ ขม(+)
  body?: -2..2,         // บาง/จืด(−) ↔ หนัก/เข้ม(+)
  sweetness?: 0..4, sourAndBitter?: boolean,  // เปรี้ยวและขมพร้อมกัน → สกัดไม่สม่ำเสมอ
  flavorTags: string[], notes?, isBest, advice?,
  createdAt, updatedAt
}

Settings { language, units, theme, lastBackupAt, defaultMethod }
```

> ค่าที่คำนวณได้ (ratio, EY, days off roast, cost) **ไม่เก็บซ้ำ** — คำนวณจาก util กลาง เพื่อให้ตัวเลขถูกต้องเสมอ

**กติกาที่ล็อกไว้ในขั้น 2** (โค้ด: `src/domain/`, `src/db/`)
- เวลาเก็บเป็น ISO 8601 UTC, `roastDate` เก็บเป็น `YYYY-MM-DD` ท้องถิ่น · หน่วยเก็บเป็น g / °C / วินาทีเสมอ (แปลงหน่วยที่ UI)
- Espresso: `waterG` = น้ำหนักช็อตเป้าหมาย (ratio = ช็อต ÷ กาแฟ)
- สูตรตั้งต้นใช้ ID คงที่ `default-<method>` และ seed ใหม่ทุกครั้งที่เปิดแอป (แก้ไม่ได้ ต้องทำสำเนา)
- `remainingG` ปรับใน Transaction เดียวกับการเพิ่ม/แก้/ลบบันทึกการชง (`src/db/brews.ts`) — ย้อนกลับได้ตรงกรัม
- `balance` แทน `acidity` เดิม เพราะ "Acidity" ในกาแฟ Specialty เป็นรสที่ดี ไม่ใช่อาการผิดปกติ — ชื่อใหม่ตรงกับสไลเดอร์ เปรี้ยว↔ขม
- Dial-in Advisor คืนค่าเป็น **รหัส** (`kind`, `adjustment`, `notes`) ไม่ใช่ข้อความ → แปลภาษาที่ UI

**กติกาที่ล็อกไว้ในขั้น 3** (โค้ด: `src/db/beans.ts`, `src/db/gear.ts`, `src/features/beans|gear/`)
- **ลบเมล็ดที่มีประวัติการชงไม่ได้** (`BeanInUseError`) → ใช้ Archive แทน; เมล็ดที่ Archive ซ่อนจากรายการ แต่ประวัติและ Insights ยังอ้างอิงได้ (ขั้น 4 ต้องไม่ให้เลือกเมล็ดที่ Archive ตอนชงใหม่: ใช้ `listBeans()` ค่าเริ่มต้น)
- **ลบอุปกรณ์ได้เสมอ** และไม่แตะประวัติการชง → `Brew.grinderId/brewerId` อาจชี้ไปอุปกรณ์ที่ไม่มีแล้ว ฝั่งประวัติ (ขั้น 7) ต้องแสดงเป็น "อุปกรณ์ที่ลบแล้ว"
- ฟิลด์ที่ไม่มีค่า = ไม่มีคีย์ในฐานข้อมูล (`stripUndefined`); ส่ง `undefined` ใน `updateBean/updateGear` = ล้างฟิลด์
- `remainingG` ติดลบได้ในฐานข้อมูล แต่ UI แสดง ≥ 0 (`remainingDisplayG`); ใกล้หมด = ≤ 20% ของถุงหรือ ≤ 30 g
- วันที่คั่วในฟอร์ม **ไม่มีค่าเริ่มต้น** (กัน "วันหลังคั่ว" ผิดโดยไม่รู้ตัว) และห้ามเป็นวันในอนาคต
- ตัวเลขในฟอร์มเก็บเป็น string แล้วแปลงด้วย `parseNumber` (รับ `,` เป็นทศนิยม) · Hook `useLive()` (`src/db/useLive.ts`) อ่าน IndexedDB แบบสด ใช้ซ้ำได้ในขั้นถัดไป
- ข้อความภาษาไทยยัง hard-code ในคอมโพเนนต์ ยกเว้นป้ายตัวเลือกที่รวมไว้ที่ `features/labels.ts` → ย้ายเข้า i18n ในขั้น 9

## 7. โครงสร้างโปรเจกต์

```
src/
  app/          # routing, layout, bottom nav
  db/           # Dexie schema, repositories
  domain/       # สูตรคำนวณ, default recipes, dial-in rules (pure TS + unit tests)
  features/
    beans/  gear/  brew/  assistant/  log/  insights/  export/  settings/
  components/   # ปุ่ม, input ตัวเลข +/–, การ์ด, ฯลฯ
  i18n/         # th.json, en.json
```

`domain/` เป็น **Pure TypeScript ไม่มี UI** → ทดสอบง่าย และนำไปใช้ซ้ำได้ (เช่น ทำ Native app ภายหลัง)
